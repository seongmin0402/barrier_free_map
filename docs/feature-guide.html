    elevator 모드stairs×6.5 · 승강기 우선 경로 강제

    segmentTypes경로 구간별 유형 보존 → TBT·배지·시각화

export function edgeWeight(type: WalkwayType, mode = "shortest"): number {
  case "stairs":   return mode === "elevator" ? 6.5 : 2.6;
  case "elevator": return 0.22;
  case "ramp":     return mode === "elevator" ? 1.02 : 1.05;
  ...
}

승강기 통합 경로 최적화

★★★

최단 거리와 크게 다르지 않으면 편의 승강기를 우선하고, 복도 인접 승강기는 실제 환승 노드로 반영합니다.

  • ★★★
    Comfort75m/+45m/1.15 · 계단 절감 시 1.22/+55m
  • ★★★
    Corridor Hub55m 이내 승강기 반드시 경유 후보
  • ★★☆
    패널티역방향(progress<0.05) · 다중환승+130m · 미이용+130m
개념 — 3가지 정책
Comfort Elevator
우회 ≤75m(close) · 추가 허용 +45m · 비율 1.15 이내면 comfort 채택. 계단 절감 시 확장 1.22/+55m.
Corridor Hub
기준 경로 선형에서 55m 이내 승강기는 “지나침”이 아니라 반드시 경유하는 후보 경로 생성.
패널티
progress<0.05 역방향 승강기 · 다중 환승(2회+) +130m · 계단 多인데 승강기 미사용 +130m 패널티.
기술 구현
상수값역할

ELEVATOR_COMFORT_RATIO1.15상대 허용 비율
ELEVATOR_COMFORT_EXTRA_M45절대 추가 거리
ELEVATOR_ON_CORRIDOR_M55복도 인접 승강기 허용
EXTRA_ELEVATOR_STOP_PENALTY_M130다중 환승 패널티
NO_ELEVATOR_PENALTY_M130승강기 미이용 패널티

SLIDE 4 / 8Dijkstra + 비용
Dijkstra + 접근성 비용 모델
거리만이 아닌 edgeWeight로 계단 회피·승강기 우대
  • 비용 = 거리 × edgeWeight단순 거리가 아니라 구간 유형 배수를 곱한 값으로 최적 경로를 찾음
  • stairs ×2.6계단은 2.6배 비싸게 계산 → 알고리즘이 계단 경로를 피함
  • elevator ×0.22승강기는 0.22배로 싸게 → 승강기 우회가 자연스럽게 선택됨
  • crosswalk ×1.1횡단보도는 보행로보다 약간 비싸게(대기·주의 반영)
  • elevator 모드 stairs ×6.5승강기 우선 옵션 — 계단 가중치를 6.5배로 올려 계단을 강하게 회피
  • segmentTypes경로를 계단·승강기·횡단보도 등 구간별로 나눠 TBT·배지에 활용
